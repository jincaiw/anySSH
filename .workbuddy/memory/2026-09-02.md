# 2026-09-02

## v0.12.0 发布（jincaiw/anySCP）

- 首次 Release run（33572707854）4 个构建 job 全挂，诊断出三个独立根因并修复（commit `91bb9e9`）：
  1. macOS ×2：GitHub 缺失 secret 渲染为空字符串但变量"存在"，Tauri 把空 `APPLE_CERTIFICATE` 当已配置签名 → 钥匙串导入空证书失败。修复：新增 "Configure optional signing environment" 步骤，仅当 secret 非空才写入 `$GITHUB_ENV`。
  2. Windows：`package-portable.mjs` 用 `new URL().pathname` 取根目录，Windows 得到 `D:\D:\...`。修复：`fileURLToPath()`。
  3. Linux：打包实际成功，挂在上传步骤——`ls *.zip *.tar.gz` 中 zip glob 不匹配 → ls exit 2 → pipefail 下整步静默失败。
- 第二次 run（33574395110）：macOS 签名修复生效（tauri-action ✓、打包 ✓），但上传又挂——macOS 交叉编译产物在 `target/<triple>/portable/`，比 `target*/portable` glob 深一层。修复：改用 `find -path "*/portable/*"`（commit `bab44b9`），find 无匹配也 exit 0，天然 pipefail 安全。
- 教训：glob 修 CI 路径问题时先看产物实际层级；`--target` 交叉编译会多一层 triple 目录。
- 第 3 轮 run（33575597419）**全绿**：Windows 新根因是 Git for Windows 的 GNU tar 优先于系统 bsdtar，`tar -a -cf D:\...` 把 `D:` 当远程主机（"Cannot connect to D: resolve failed"）且 GNU tar -a 不支持 zip。修复（commit `c9817c6`）：显式调用 `%SystemRoot%\System32\tar.exe`（Windows 自带 bsdtar），缺失时回退 PowerShell `Compress-Archive`。
- v0.12.0 已正式发布：https://github.com/jincaiw/anySCP/releases/tag/v0.12.0 ，13 个资产（2×dmg、deb/AppImage/rpm、msi/setup.exe、2×app.tar.gz、4×portable 包）。
- 流程：修 workflow 必须移 tag 重推（Actions rerun 用原始 SHA 的 workflow 文件）；等当前 run 完再移 tag，避免并发上传同一草稿 Release。
