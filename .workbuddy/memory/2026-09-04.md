# 2026-09-04

## 堡垒机空密码触发短信修复 → v0.14.20（09:30–10:10）

- 用户实测反馈：空密码连接**不会**触发服务端下发短信验证码；输入任意错误密码**可以**触发（v0.14.13 的"首个密码提示答空"策略与该堡垒机实际行为不符，且密码为空时策略 B 被整体跳过）。
- 根因：`auth_with_password` 中 `if empty_first && password.is_empty() { break; }` 跳过策略 B + 策略 B 触发应答恒为空串。
- 修复（commit 7442de0）：新增 `EMPTY_PASSWORD_TRIGGER = "anyssh"` 常量与 `dual_factor_trigger_answer(password)` 纯函数——策略 B 触发应答改为"与策略 A 不同的值"：有密码→空串（保留原语义），空密码→非空占位值（满足"非空应答才触发短信"类堡垒机）；策略 B 不再因空密码跳过。策略 B 仅在 A 被拒后执行，普通主机不受影响（B 被拒后回落 plain password）。
- 测试：新增 `empty_password_trigger_is_a_non_empty_dummy`（触发值非空断言 + 空密码端到端应答走查），改写 `empty_first_strategy_triggers_then_answers_password` 复用新函数。244 Rust 测试绿、clippy/fmt 干净、tsc/i18n parity 绿。
- 前端：passwordDualFactorHint（中英）补充"若尚未收到短信验证码，可先留空密码连接一次以触发短信下发"。
- 发布：main CI 33826559530 绿（12m）→ tag v0.14.20 → Release run 33827263380（15m，25/25 资产）→ Latest 发布，双语 notes（.workbuddy/temp/release-notes-v0.14.20.md）→ 端点返回 0.14.20。
- 待用户实测：① 空密码连接一次 → 手机收短信；② 重连输入"静态密码+动态码"拼接串。
