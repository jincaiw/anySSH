# 2026-09-04

## 堡垒机空密码触发短信修复 → v0.14.20（09:30–10:10）

- 用户实测反馈：空密码连接**不会**触发服务端下发短信验证码；输入任意错误密码**可以**触发（v0.14.13 的"首个密码提示答空"策略与该堡垒机实际行为不符，且密码为空时策略 B 被整体跳过）。
- 根因：`auth_with_password` 中 `if empty_first && password.is_empty() { break; }` 跳过策略 B + 策略 B 触发应答恒为空串。
- 修复（commit 7442de0）：新增 `EMPTY_PASSWORD_TRIGGER = "anyssh"` 常量与 `dual_factor_trigger_answer(password)` 纯函数——策略 B 触发应答改为"与策略 A 不同的值"：有密码→空串（保留原语义），空密码→非空占位值（满足"非空应答才触发短信"类堡垒机）；策略 B 不再因空密码跳过。策略 B 仅在 A 被拒后执行，普通主机不受影响（B 被拒后回落 plain password）。
- 测试：新增 `empty_password_trigger_is_a_non_empty_dummy`（触发值非空断言 + 空密码端到端应答走查），改写 `empty_first_strategy_triggers_then_answers_password` 复用新函数。244 Rust 测试绿、clippy/fmt 干净、tsc/i18n parity 绿。
- 前端：passwordDualFactorHint（中英）补充"若尚未收到短信验证码，可先留空密码连接一次以触发短信下发"。
- 发布：main CI 33826559530 绿（12m）→ tag v0.14.20 → Release run 33827263380（15m，25/25 资产）→ Latest 发布，双语 notes（.workbuddy/temp/release-notes-v0.14.20.md）→ 端点返回 0.14.20。
- 待用户实测：① 空密码连接一次 → 手机收短信；② 重连输入"静态密码+动态码"拼接串。
- 发布后巡检：v0.14.20 为 Latest、端点 0.14.20、无 open issue/PR；7442de0 与 4aec481 的 CI 均绿。全部闭环，等待用户堡垒机实测结果。

## 空密码仍不触发短信：两道前端/后端闸门 → v0.14.21（11:18–11:55）

- 用户实测 v0.14.20 反馈：身份认证弹窗和编辑主机页空密码连接仍不触发短信，错密码可以（附截图，弹窗已显示 v0.14.20 新提示文案，确认用户已升级）。
- 根因（两道闸门，均早于 v0.14.20 的后端修复生效点）：
  1. **PasswordPromptModal.tsx 前端校验**：`if (!password)` 报"密码不能为空"，空提交直接被拦，连接请求根本不发出。
  2. **commands.rs resolve_auth_method**：空 password_override 被 `filter(|p| !p.is_empty())` 丢弃回落 vault；vault 中空保存密码直接报错（此前"严格化"修复所为）。
- 修复（commit d22cd82）：弹窗允许空提交（移除 error 状态及未用的 passwordRequired i18n 键）；resolve_auth_method 空 override 按字面采用、vault 空密码放行（vault **读取失败**仍报错，不回退空串）。has_saved_password 保持空=false → 弹窗。
- 完整链路（修复后）：空密码连接 → 策略 A 全空应答（不触发）→ 策略 B 触发提示答 "anyssh"（非空）→ 服务端下发短信 → 用户重连输入"静态密码+动态码"。
- 验证：244 Rust + 147 前端测试绿、clippy/fmt/tsc 干净、无 e2e 依赖旧校验。发布 v0.14.21（25/25 资产、Latest、端点 0.14.21）。
- 教训：v0.14.20 只修了 ki_attempt 内部逻辑，未端到端走查"空密码从 UI 到 SSH 层"的完整链路——前端校验和 resolve_auth_method 的历史拦截都让修复不可达。涉及认证行为的修复必须沿数据流全链路验证。
- 发布后巡检：v0.14.21 为 Latest、无 open issue/PR；d22cd82 与 fa688e4 的 CI 均绿。全部闭环，等待用户升级 v0.14.21 后实测空密码触发短信。
