# 2026-09-08

## russh 0.46 → 0.63.2 升级评估（未实施，待用户确认）

产出：`docs/russh-0.63-upgrade-plan.md`（评估 + 分步实施方案）。

关键结论（通过下载 russh 0.63.2 / ssh-key 0.7.0-rc.11 源码逐项核对）：
- 可行，建议一次性直跳。项目只用 russh 客户端能力，不碰 0.62 的 server-side channel_open breaking change。
- **vendored russh 补丁可退役**：本地补丁仅为 `Handle::take_last_auth_methods`（暴露 USERAUTH_FAILURE 的 remaining methods）；上游 0.50 起 `AuthResult::Failure { remaining_methods: MethodSet, partial_success }` 已原生提供。改完即可删 `src-tauri/vendor/russh/` 与 `[patch.crates-io]`。
- **最大坑：默认算法表变化**（0.63.2 `src/negotiation.rs`）：kex 首位新增 `mlkem768x25519-sha256`；`Preferred::DEFAULT.key` 已自带 `ssh-rsa`（我们原来的 push 会重复）；**SHA-1 MAC 被移出默认表** → 必须显式加回 `mac::HMAC_SHA1`，否则旧设备 aes-cbc 组合协商失败，且在 0.63.1 安全语义下 CBC+none MAC 会 panic。`Preferred` 还新增 `host_key_certificates` 字段。
- 其他 breaking：`russh-keys` 并入 `russh::keys`（0.50）；Handler 原生 async trait（删 `#[async_trait]`）；`check_server_key` 收 `PublicKeyOrCertificate`（0.63）；`fingerprint()` 需传 `HashAlg` 且 Display 自带 `SHA256:` 前缀（**已核对与旧格式一致，SQLite 已存主机指纹无需迁移**）；`authenticate_*` 返回 `AuthResult`（用 `.success()`）；`PrivateKeyWithHashAlg::new(Arc<PrivateKey>, Option<HashAlg>)`；`ChannelMsg::Data` 载荷 `CryptoVec`→`bytes::Bytes`（生产代码零改，仅 scp/exec.rs 测试）。
- Cargo 特性建议：`default-features=false, features=["ring","rsa","flate2","des"]` —— 避开 aws-lc-rs 的 C 构建链并可复用 rustls 的 ring 0.17；`des` 是 3des-cbc 必需。
- russh 0.63.2 `=`锁定预发布依赖 `ssh-key 0.7.0-rc.11` / `rsa 0.10.0-rc.18` / `pkcs1 0.8.0-rc.4`（CI 无 audit，不阻断，但需知悉）。
- russh-sftp 2.1.1 与 russh 解耦（仅 dev-dep），本次建议不动。
- MSRV 1.89 / edition 2024；本机 rustc 1.96.1、CI `dtolnay/rust-toolchain@stable` 均满足。

待用户确认的 4 个决策点：加密后端（ring vs aws-lc-rs）、是否加回 SHA-1 MAC、russh-sftp 是否同步升级、是否接受 rc 传递依赖。

## 决策点 1 复审：ring vs aws-lc-rs（结论：ring）

- 纠正旧认知：aws-lc-rs 非 FIPS 构建已**不需要** cmake/go/bindgen（预生成 bindings），仅需 C 编译器；但 **Windows x64 仍需 NASM**，否则必须启用 `prebuilt-nasm` feature 或设 `AWS_LC_SYS_PREBUILT_NASM=1`（依据 aws-lc-rs 官方 README，2026-09 核对）。
- 性能口径（russh 0.53 release notes）：AEAD 重构后 ring 已有 ~2x 提升，aws-lc-rs AES-GCM ~10x——SSH/SFTP 传输 <1Gbps 场景碰不到加密瓶颈，性能不构成选型理由。
- 决定性因素：① 项目 rustls 0.23/tokio-rustls/reqwest 已统一 ring，全应用单一加密后端；② release.yml 四平台矩阵零加密安装步骤，aws-lc-rs 需给 Windows 加 NASM/prebuilt-nasm；③ 桌面端无 FIPS 诉求；④ 未来切换仅一条 feature，russh API 层无差异。
