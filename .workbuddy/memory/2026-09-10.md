### 方案有 4 处判断与上游实际不符（重要，下次评估同类升级时先验证）

1. **版本已变**：实施当日 crates.io 最新稳定版是 **0.63.3**（非方案写的 0.63.2）。
2. **`ssh_key::HashAlg` 没有 `Sha1` 变体**（只有 Sha256/Sha512）。SHA-1 对 RSA 用 **`None`** 表达 —— `PrivateKeyWithHashAlg::new` 文档：「For RSA, passing None is mapped to the legacy sha-rsa (SHA-1)」，且对非 RSA 直接置 None。回退链实为 `Some(Sha512) → Some(Sha256) → None`。
3. **`AuthResult` 只在 `russh::client` 下 re-export**（`client/mod.rs:60`），**未在 crate 根导出**，方案写的 `use russh::client::AuthResult;` 语义上要按路径理解。
4. **russh-sftp 最新是 3.0.0**（2026-09-08 发布，方案定稿时是 2.4.0）。已逐版本 diff 源码确认对本项目零影响，用户确认后升 3.0.0。

- **russh-sftp 2.4.0 / 3.0.0 已完全不依赖 russh**（russh 只在 dev-dependencies）→ transport-agnostic，与 russh 版本互不约束。`SftpSession::new` / `close` 在 2.1.1/2.4.0/3.0.0 签名一致；2.4.0→3.0.0 客户端 pub fn **零变化**（仅 io::Error 超时映射 + 协议模块内部重构）。

## 六模块（本地终端/SSH/telnet/RDP/VNC/串口）深度审查 + 修复

jason 指令：「对本地终端、ssh、telnet、RDP、VNC、串口的功能实现进行深度检查，并修复问题和bug」。

产出 4 个提交（分支 `workbuddy/main-32c9b278`，已推远端，CI run `34503319961` 验证中）：
`9349bad` term 层 / `986ad81` ssh / `00270ac` remote / `e676bf6` vnc 前端。基线 303 测试仍全绿，clippy -D warnings 零告警。

### 最高价值的两个发现（都是同类根因，两处代码都中招）

1. **`select!` 分支体内 await 不可取消** → 会话关闭挂死。
   `term/mod.rs`（write/resize）与 `ssh/session.rs`（channel.data/window_change）都是。分支一旦被选中就无法取消，后端不排空时整个循环冻结，包括 `Close`/`Eof` 分支 → `term_close` / `ssh_disconnect` 永久 await。
   修：操作加 `IO_OP_TIMEOUT`/`CHANNEL_OP_TIMEOUT`(5s)；`close()` 用 `timeout(&mut task)` + `task.abort()`。
   **坑**：`tokio::time::error::Elapsed::into_inner()` 在所用 tokio 版本**不存在**（编译才发现）；正确做法是 `timeout(dur, &mut join_handle)`（JoinHandle: Unpin，`&mut F` 是 Future），超时后仍能 abort。

2. **portable-pty 的 `Child::kill()` 只发 SIGHUP 且只杀单 pid**（读上游 0.9.0 `src/lib.rs:347` 实证）。其 spawn 里 `setsid()`（`src/unix.rs:257`）→ **pid == pgid**，所以 `kill(-pid, SIGKILL)` 能杀整组。
   原代码 `spawn_blocking(child.wait())` 无超时，shell trap HUP 或前台作业持有 slave 时永不返回 → 关标签页挂死 + 阻塞线程泄漏。修：SIGHUP → `try_wait()` 轮询 2s → 进程组 SIGKILL → reap（为此加 `libc = "0.2"` 直接依赖）。

### 其余修复
- 串口/本地 PTY 读线程把一切错误塌缩成 EOF（拔线、PTY 塌陷表现与正常退出一致）→ 通道改传 `io::Result`，前端能分辨原因。
- `read()` 用 `min(buf.len())` 截断并**丢弃尾部**（三个后端都有，当前仅因缓冲区恰好相等而未触发）→ 加 `pending` 缓冲。
- 会话日志 `str::from_utf8` 失败即整块丢弃（多字节跨 chunk 被切）→ `from_utf8_lossy`。
- telnet：登录脚本匹配后 `buffer.clear()` 丢掉同 chunk 尾部的下一个提示符（设备常一次发 Username+Password）→ `drain(..m.end())`；脚本发送字节**未做 IAC 转义**（用户键入路径做了）→ 两处补 `iac_escape`；**从不主动发 `WILL NAWS`** → 不协商的设备永远 80×24。
- bridge：孤儿 pending token 永不过期 → 监听器+端口永驻 → 加 60s TTL；上游不可达直接 return 无 Close 帧 → noVNC 显示无信息错误 → 发带原因的 Close 帧；补 `set_nodelay(true)`。
- RDP：握手错误绑到 `_err` 丢弃且 PDU 不带文本（证书变更/TLS 失败/连接被拒现场无法区分）→ 记 `tracing::warn!`；`probe_variant` 的 TCP connect 无超时 → 加 10s。
- VNC 前端：`t`（`useTranslation` memo 在 `[locale]`）进了连接 effect 依赖 → **切语言会断开 VNC 会话且无法自愈**（`RdpCanvas` 无此问题，可作对照）→ 改 ref；`String(error)` 对 Tauri 的 `{kind,message}` 渲染成 `[object Object]` → 复用 `messageOf`；`disconnect` 丢弃 `reason` 且 `clean` 缺省 true。
